# Horizontal Scaling for MinIO

MinIO uses distributed erasure coding across all nodes. The replica count must always be a **multiple of 2** (2, 4, 6, ..., up to 32).

:::note
MinIO tracks replica history internally. When scaling out, new nodes join the pool. When scaling in, data is rebalanced automatically before nodes are removed.
:::

## Scale Out

Add 2 replicas (e.g., from 2 to 4):

```bash
kubectl apply -f - <<EOF
apiVersion: operations.kubeblocks.io/v1alpha1
kind: OpsRequest
metadata:
  name: minio-scale-out
  namespace: demo
spec:
  clusterName: minio-cluster
  type: HorizontalScaling
  horizontalScaling:
    - componentName: minio
      scaleOut:
        replicaChanges: 2
EOF
```

Monitor progress:

```bash
kubectl get opsrequest minio-scale-out -n demo -w
```

## Scale In

Remove 2 replicas (e.g., from 4 to 2):

```bash
kubectl apply -f - <<EOF
apiVersion: operations.kubeblocks.io/v1alpha1
kind: OpsRequest
metadata:
  name: minio-scale-in
  namespace: demo
spec:
  clusterName: minio-cluster
  type: HorizontalScaling
  horizontalScaling:
    - componentName: minio
      scaleIn:
        replicaChanges: 2
EOF
```

:::caution
Scaling in removes nodes from the pool. Ensure your data has sufficient redundancy before scaling in. Do not scale below 2 replicas.
:::

## Cleanup

```bash
kubectl delete opsrequest minio-scale-out minio-scale-in -n demo --ignore-not-found
```
